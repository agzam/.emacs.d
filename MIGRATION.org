* Testing & CI
- =bb test= - buttercup suites from tests/ (buttercup auto-installed into
  ~/.cache/emacs-lab/test-elpa); =bb lint= - check-parens over tracked
  elisp; =bb smoke= - full elpaca boot behind a pty, verdict from the
  marker file scripts/smoke-check.el writes (SMOKE-OK/FAILED/TIMEOUT);
  =bb ci= - deps + lint + test.
- Workflow (.github/workflows/ci.yml): =test= job (bb ci, cached
  test-elpa) and =smoke= job (cached ~/.local/share/emacs-lab + eln with a
  restore-keys prefix, since elpaca is unpinned). Emacs 30.1 is the floor
  (built-in which-key, completion-preview); local dev may run newer
  (31 pretest as of 2026-07).
- RULE for every future port: the module lands together with a new or
  extended suite in tests/. Layout mirrors the source tree -
  tests/MODULE/FILE-tests.el per module source file (autoload/ level
  flattened; lisp/ sources under tests/lisp/), shared tests/helper.el found
  via locate-dominating-file. helper.el sandboxes XDG dirs, so the
  quarantine wiring itself is testable.
- Gotchas: buttercup-run-discover needs an ABSOLUTE tests dir; deleting an
  autoload/*.el leaves stale generated loaddefs (also rm
  ~/.cache/emacs-lab/autoloads/NAME.el); general/autoload/url.el has a
  top-level (require 'ghub) - its commands error and the file cannot load
  in tests until the git module ports.
- The smoke job doubles as the Linux-parity trial gate - keep it green.

Idiom verified against the elpaca manual on disk (doc/manual.org,
"recipe-keyword-repo", elpaca 0.12): a bare local path in =:repo= with no
=:host= builds IN PLACE from that directory - edits there get picked up on
=elpaca-rebuild=, nothing is cloned:
#+begin_src emacs-lisp
(use-package foo
  :ensure (foo :repo "~/GitHub/agzam/foo/"))
#+end_src
The cons form =:repo ("~/path" . "name")= CLONES into
elpaca-sources-directory instead - avoid it for the work-locally flow.
The path should be a git repo root (elpaca runs git ops against it):
remoto.el is already shaped right; the ~/.doom.d/modules/*/-embedded ones
are not and need extraction first.

Layout decision DEFERRED (2026-07): leaning separate repos under
~/GitHub/agzam/ per package; decide for real at the first consuming port
(elisp or git module). The packages/-dir-inside-config alternative needs a
smoke-boot experiment first (subdirs are not git roots).

Latent dep, fix with this pattern: general module already references
let-plist (autoload/url.el x4, autoload/misc.el open-circleci-log) - those
commands error until let-plist lands (or the elisp module ports).
