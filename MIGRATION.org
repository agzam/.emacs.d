#+title: Doom migration plan
#+startup: overview

Reshuffle headings to set priority; port top-down. Keep entries updated as
modules land (see AGENTS.md for porting conventions - naming, quarantine,
module layout).

* Ported so far
- core :: elpaca bootstrap (repos/builds in ~/.local/share/emacs-lab/), doom-compat
  (macros, first-hooks incl. switch-frame, modulep!, quarantine), doom-keybinds
  (map!, SPC/"," leaders), doom-defaults (baseline editor/UI defaults,
  doom/escape, MODE-local-vars hooks, built-ins: recentf/saveplace/so-long/
  auto-revert/comint/compile/ediff/show-paren/transient), lazy loaddefs
  generation, XDG cache/state layout
- modules :: evil (lean set), bindings (Doom tree, company/ivy/helm excised,
  SPC p on project.el), git (magit/forge stack, local-dev recipe hook),
  general (incl. smartparens base + persistent-scratch-as-*scratch*),
  completion, colors (circadian stack), modeline (doom-modeline),
  elisp (eval/edebug/profiler + let-plist/evilify-edebug folded in),
  dired (treemacs suite), org (core slice: roam/vulpea/evil-org)
- user layer :: config.el (leader tree, globals), lisp/functions.el
  incl. reload-config (SPC h r r; doom/reload analogue - re-runs
  defaults/modules/config in place, elpaca picks up new packages; restart
  still needed for doom-compat/doom-keybinds, the elpaca bootstrap and
  active-modules changes; edited autoload/*.el still want a direct
  load-file)
- root packages.el :: ligature, helpful, golden-ratio, lorem-ipsum,
  consult-symbol (ahead of search); evil extras stay disabled by omission
- testing/CI :: buttercup suites (tests/, XDG-sandboxed via helper.el),
  bb.edn tasks (deps/lint/test/smoke/ci), scripts/{lint,smoke-check}.el,
  GitHub workflow (test + smoke jobs on Emacs 30.1, cached elpaca dirs)

* Key clusters
The key audit kills the "binding X silently missing" whack-a-mole:
mechanical keymap dumps diffed per cluster, every differing entry gets an
explicit verdict in key-decisions.edn (:ported / :improved / :dropped /
:deferred + note). Migration-scoped tooling - retire when the last cluster
closes (teardown TODO below).

Workflow, one cluster per sitting - any future session (human or LLM)
resumes from this section alone:
1. Regenerate BOTH dumps at the start of a sitting; dumps are throwaway
   snapshots, never trust old ones.
   - Doom side: eval the walker half of scripts/dump-bindings.el
     (everything above its "Boot mode" section; standalone vanilla elisp,
     pure functions) inline in the live Doom session, then
     (dump-bindings "~/.cache/emacs-lab/doom-keys.eld").
     Never load-file lab files into Doom.  dump-bindings-load-autoloads
     stays nil there (no force-loading in a live session) - doom-side
     :void-suffix detection is best-effort; keydiff only reads lab flags.
   - Lab side: =bb keydump= (pty boot; KEYDUMP_REQUIRE env forces
     features whose maps bind lazily).
2. =bb keydiff= - org report at ~/.cache/emacs-lab/keydiff.org (generated,
   never hand-edited), console shows open/broken/parked/regression counts
   per cluster; exit 1 on regressions (a :ported entry that drifted).
   Broken = bound to a void command, or a transient prefix whose layout
   references void suffix commands (lab dump marks those :void /
   :void-suffix); only a :deferred verdict parks one, other verdicts
   can't silence it.
3. Pick an unchecked cluster below. For each open entry record a verdict
   in key-decisions.edn and port/improve as decided - the binding itself
   is what closes a diff entry; a :ported ledger line is optional
   bookkeeping that buys drift detection. Rerun 1-2 until the cluster
   shows 0 open, tick it here, put session-worthy calls in the
   Decisions log.

Module-port rule: when a module lands, flip its :deferred ledger entries
and re-review its cluster. Coverage: leader tree + evil g/z/[/] prefix
trees; localleader and mode-local maps get scoped dumps later if needed.
